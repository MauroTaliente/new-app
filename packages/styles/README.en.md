# @lib/styles

## `lib-styles-generate` — config

The CLI walks **up** from `cwd` looking for (first match wins):

- `.lib.config.json`
- `lib.config.json`
- `lib-styles.config.json`

### JSON Schema — IDE autocomplete

You **do not** need to repeat `$schema` in every `lib.config.json` if the repo defines **`json.schemas`** in `.vscode/settings.json` (Cursor/VS Code): map `**/lib.config.json` to `./node_modules/@lib/styles/lib.config.schema.json` from the **workspace root** (where `node_modules` lives after `pnpm install`).

If you open only a subfolder as the workspace or use another editor, declare the schema in the JSON file:

```json
{
  "$schema": "./node_modules/@lib/styles/lib.config.schema.json",
  "libStyles": {
    "fromCss": "./src/theme",
    "domainsOrder": ["tokens", "palette", "theme"],
    "output": "./src/theme/styles.generated.ts"
  }
}
```

Package export: `@lib/styles/lib.config.schema.json` (alias: `lib-styles.schema.json` → same file).

Use a `libStyles` object:

```json
{
  "libStyles": {
    "fromCss": "./src/theme",
    "domainsOrder": ["tokens", "palette", "theme"],
    "output": "./src/theme/styles.generated.ts",
    "excludeStems": ["scratch", "wip"],
    "metaSourceStem": "tokens",
    "banner": "// Generated by lib-styles — do not edit.",
    "verbose": false,
    "watch": false
  }
}
```

(Omit `$schema` when using the workspace association.)

### Paths

- `fromCss`, `output`, `outputDir` are resolved **relative to the config file’s directory** (like `tsconfig.json`).

### Order of domains (cascade / `var()` resolution)

1. **`--domains` on the CLI** (highest priority)
2. **`libStyles.domainsOrder`** in config
3. **Otherwise**: every `*.css` in `fromCss`, sorted **A→Z** by filename (locale `en`, base sensitivity).  
   Files named `*.generated.css` are ignored.  
   Stems listed in **`excludeStems`** are skipped (only applies to this auto-discovery mode).

### Other `libStyles` fields

| Field | Purpose |
|-------|--------|
| **`excludeStems`** | Stems to skip when discovering files (e.g. `scratch.css`). Not applied when `domainsOrder` is set. |
| **`metaSourceStem`** | Which file supplies `@theme` meta (`--theme-default`, `--theme-cols`) and grid cols fallback. Default: stem `tokens`, else first domain. |
| **`banner`** | First line(s) of the generated `.ts` (default: `// Auto-generated from CSS…`). |
| **`verbose`** | Print resolved config path, `fromCss`, cascade order, and output path. |
| **`watch`** | Watch `fromCss` and regenerate on change. Same as CLI `--watch`. Use **`--no-watch`** to run once even if `watch` is `true` in config. |

### Shipped defaults (`packages/styles/defaults`)

If you point at this package’s `defaults` folder **without** `domainsOrder` and without CLI `--domains`, the order is fixed to `tokens` → `palette` → `theme` (alphabetical order would break token resolution).

### CLI overrides

| Flag | Effect |
|------|--------|
| `--from-css <dir>` | Input directory |
| `-o` / `--output <dir>` | Output **directory** for `styles.generated.ts` |
| `--domains a,b,c` | Stems in order |
| `--config <path>` | Use this JSON file instead of searching |
| `--no-config` | Ignore config files |
| `--verbose` / `-v` | Same as `libStyles.verbose: true` |
| `--watch` / `-w` | Same as `libStyles.watch: true` (overrides `false` in config) |
| `--no-watch` | Force a single run (`libStyles.watch` ignored) |
